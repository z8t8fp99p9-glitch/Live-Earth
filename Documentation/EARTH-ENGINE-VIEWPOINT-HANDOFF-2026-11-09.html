Current contract

  • EarthEngine/Core/earth-engine.js owns the global quaternion viewpoint and view-transition lifecycle.
  • The transferable state is only {x, y, z, w}; cameras, zoom, scenes, renderers, surface alignment, feature layers and Moon state are never transferred.
  • The pre-transition event captures the exact outgoing owner’s registered group. The named owner is authoritative over a potentially stale cached group pointer.
  • The post-transition event applies the saved quaternion to the incoming group immediately. A group created asynchronously later receives the current snapshot during registration.
  • The sole persisted key is liveEarthGlobalViewpointV1. Old Home-only V3/V2/V1 data is not read or migrated.
  • Home uses Engine quaternion interactions with locked zoom. Independent Earth View uses the same Engine interaction controller with its own camera adapters.
  • Stacks overlays without their own globe reuse Home’s registered Earth group.

Retired components

  • EarthEngine/Core/earth-viewpoint-bridge.js has been deleted.
  • Tests/earth-viewpoint-bridge.test.cjs has been replaced by Tests/earth-engine-viewpoint.test.cjs.
  • The obsolete bridge was removed from the Service Worker app shell. The cache identity is now v129-engine-quaternion-viewpoint.

Verification

The focused regression test verifies that legacy V3 is ignored, the exact outgoing owner is captured, Home receives the outgoing quaternion synchronously, and Home remains quaternion-only with locked zoom. The broader JavaScript and Python regression suites pass. Installed-device confirmation is still required to verify the observed multi-second delay is eliminated.

Protected boundaries

No Home camera, framing, star field, Moon orbit/path, Location marker state, lighting ownership, Orb presentation, or independent Sun/Moon controller was changed by the viewpoint cleanup. The assistant prepares a root ZIP only; the owner uploads it through the repository’s ZIP extractor.
