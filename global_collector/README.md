# LIVE // EARTH — Global Collector

**Version:** 0.1.0  
**Status:** Code prepared; not integrated into live workflows; system testing deferred.

The Global Collector is the shared source-intake and normalization layer between Global Collection Manager and Global Checker.

## What it does

1. Receives a single-View collection job generated by Global Collection Manager.
2. Validates that job against all three Manager collection configuration files.
3. Confirms every source's Global Checker policy reference, View scope and exact approved feed URL.
4. Fetches bounded HTTPS RSS/Atom feeds.
5. Parses original story metadata, links, dates, authors and media-candidate metadata.
6. Normalizes records and preserves source provenance.
7. Returns a transient JSON batch for Global Checker.

## Six critical boundaries

- One Manager job contains exactly one View.
- Nature and Alien World feeds and identities are never mixed.
- A shared source catalogue is not a shared story database.
- All records are `PENDING` Global Checker review.
- Media references are candidates only; no image rights are approved here.
- No SQLite database is opened or written by this component.

## PDF blueprint alignment

The Newsroom Master Blueprint requires view-owned collection and storage, separate Nature and Alien World SQLite databases, and per-View Collector write ownership. It also requires strict source boundaries, a 32-day rolling collection horizon, source identity and provenance, and no destructive reset or shared story store.

The Global Collector is therefore implemented as shared collection mechanics. The existing Nature Collector and Alien World Collector remain their respective View-specific adapters and sole database writers during the later integration stage. Their current workflows and databases are untouched by this package.

## Configuration ownership

- `global_collection_manager/config/source-registry.json` — collection source catalogue.
- `global_collection_manager/config/view-collection-profiles.json` — independent View collection profiles.
- `global_collection_manager/config/source-view-assignments.json` — View-specific subscriptions.
- `global-checker/source-registry.json` — the separate rights/provenance authority.

The Global Collector does not duplicate, edit or override these files.

## Current limits

- RSS and Atom feeds only (`rss`, `rss_atom` connector types).
- Exact approved HTTPS source feed URLs only.
- Maximum feed response: 4 MiB by default (hard safe range: 1 KiB–12 MiB).
- HTTPS redirects must remain within the registered Global Checker feed-domain boundary.
- Network timeout: 18 seconds per request by default.
- Bounded retries: two retries after the first attempt.
- Malformed or unreachable feeds are reported; other feeds continue.
- No arbitrary article-page scraping and no image binary downloads.

## Usage

From the repository root:

```bash
python -m global_collector --job-file manager-job.json
```

The job file must be JSON produced by Global Collection Manager. Use `--job-file -` to read a JSON job from standard input.

Output is a JSON batch on standard output. The CLI never writes a feed, database or result archive.

## Deferred

The component is deliberately not connected to the current GitHub Actions workflows yet. Later integration will connect it through the Nature and Alien World Collector adapters, retain their exclusive write authority, and route their records through Global Checker before persistence.

No tests have been run for this package. The complete Newsroom test phase remains deferred until all systems are built.
